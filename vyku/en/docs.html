Install

Windows portable build: unzip the release into any folder and run vyku.exe. The portable archive carries portable.flag, so data is written to data beside the program and the whole folder moves as one.

Android: download the installer and the checksum file with the same name, verify SHA-256 first, then install. Allow "install unknown apps" for the current browser or file manager only for the install, and turn the setting back off afterwards.

Minimum system version: Android 7.0 (API 24). The value comes from the debug build manifest in dist/V0.18.0-A-android/ (aapt2 dump badging reports minSdkVersion:'24') and matches minSdk = flutter.minSdkVersion in android/app/build.gradle.kts:52 (Flutter's default, 24).

On Windows, the build configuration declares no minimum Windows version (windows/CMakeLists.txt and windows/runner assert none), so this site names no version number rather than promise something the build does not support.

No public build is available right now. The install steps above describe the flow after release; there is no installer to download today.

First run

  1. The first launch shows an empty list. Choose add, then pick a physical, digital or document asset.
  2. Fill in the required name and type; if the asset has an expiry date, add it now.
  3. For assets that need proof, add a photo or a file attachment and confirm the check passes.
  4. Open settings to confirm theme, language and data folder, and note where the data lives.
  5. Make one encrypted backup and store it off the device as your first restore baseline.

Backup and restore

  1. In settings, export an encrypted backup to get one single-file archive with the .vbk extension.
  2. Store the archive off the device, name it by date, and keep the last few copies.
  3. Before restoring, pick the archive; the app first verifies the database, the attachment manifest and the checksums.
  4. Only a passing archive is written; on failure it rolls back to the pre-restore state, so existing data is not damaged.

Moving between the portable and installed builds uses the same path: export an encrypted backup, then restore it on the other device.

Attachments

Take a photo, pick an image or pick a file. Attachments are written to the app's private directory and SHA-256 is checked before and after; a mismatch is cleaned up and reported.

The health check lists missing files, hash mismatches and orphan files, so you can confirm an archive is complete before restoring.

Reminders

Assets can carry an expiry date; the home screen groups them as expired, due soon and pending, and a reminder can jump back to its asset.

On Android the first reminder requests notification permission as needed, and pending reminders are rescheduled once permission is restored.

Platforms and limits

Check these first

Vyku is built and accepted on Windows and Android only; iOS and macOS are paused. It has no account and no cloud sync, so your data and backups are yours to keep.

  • iOS and macOS are paused: no project, no installer and no acceptance plan.
  • No account, sign-in or cloud sync, and no web data management.
  • Attachments open in the client only, with no online preview or browser access.
  • Backups have no cloud copy; losing the archive means losing the data, so keep a copy off-site.
